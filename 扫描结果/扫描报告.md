### VULN-02 整改详情（✅ 已完成）

#### 先纠正技术定性

原报告写作"调用 OpenSSL 时命令可能被注入，建议加 `shlex.quote()` 或改用参数列表"。复核代码后确认：

- **代码全程使用列表传参、未启用 `shell=True`**，因此**不存在 shell 命令注入（CWE-78）**；
- **"改用参数列表"这一项原本就已满足**，无需整改；
- **`shlex.quote()` 仅适用于 `shell=True` 场景**。在列表传参下使用它，会把引号当成字面字符传给 openssl，**导致口令永远验证失败**——因此本项目**不采用**该方案（已写入代码注释备查）。

真实问题应为 **CWE-88 参数注入 + 敏感信息暴露**：

| 实际风险 | 位置 |
| --- | --- |
| ① 两处 PFX 口令来自 HTTP 请求、未做格式校验，直接拼进 openssl 参数 | `register.py:80`（`certPassword`）、`cert_login.py:77`（`password`） |
| ② 口令以 `pass:<口令>` 形式进入**命令行**，可被进程列表/审计工具读取 | `ca_client.py`、`ca_client_crt_yanzheng.py` |
| ③ `OPENSSL_PATH` 环境变量未校验即作为可执行文件使用 | `SM2.py:37`、`SM4.py:30` |
| ④ 16 处 `subprocess.run` 分散在 4 个文件、**均无超时**、环境变量整体继承 | 全项目 |

#### 整改措施

| # | 措施 | 落点 |
| --- | --- | --- |
| 1 | **新增统一执行封装** `app/utils/openssl_runner.py`：路径校验 + 入参校验 + 命令执行三合一 | 新建文件 |
| 2 | **口令改经 stdin 传递**：读 PFX 用 `-passin stdin`，导出 PFX 用 `-password stdin`，口令不再出现在命令行 | `ca_client.py`、`ca_client_crt_yanzheng.py` |
| 3 | **口令白名单校验**：非空、≤128 字符、不以 `-` 开头、仅允许 `[A-Za-z0-9_\-.,:@#!*+=]`（接口层 + 底层各一道） | `register.py`、`cert_login.py`、`ca_client.py`、`ca_client_crt_yanzheng.py` |
| 4 | **`OPENSSL_PATH` 导入时校验**：绝对路径 + 文件存在 + 可执行 + 文件名匹配 `openssl*`，不合格直接抛错 | `SM2.py`、`SM4.py` |
| 5 | **消除硬编码 `'openssl'`**：全部改走统一路径解析，解决"PATH 版本与 `.env` 版本不一致"的隐患 | `ca.py`、`ca_client.py`、`ca_client_crt_yanzheng.py` |
| 6 | **补 30s 超时 + 最小环境变量 + 显式 `shell=False`** | `openssl_runner.py` |
| 7 | **用户名防御性校验**：`generate_client_cert` 内再校验一次，拦截 DN 注入与路径穿越 | `ca_client.py` |
