## 1. 执行摘要

本轮针对该项目的 **Flask 后端**与 **Vue3 前端**分别完成依赖成分分析与已知漏洞比对，共产生 5 份原始产物。核心结论如下：

1. **前端已闭环**：`npm audit` 初始报出 **13 条漏洞（11 高 / 1 中 / 1 低）**，全部有可用修复版本。执行 `npm audit fix` 后复查为 **0 条**；关键包版本从 `axios 1.13.x / vue 3.5.25 / vite 7.3.1` 提升至 **`axios 1.20.0 / vue 3.5.43 / vite 7.3.7`**，`package.json` 的语义化版本约束未被破坏，`npm run build` 构建通过。
2. **后端共 75 条漏洞，分布在 10 个包**，去重后为 **39 个唯一漏洞编号**（含 33 个 CVE 别名）。其中 **`pyjwt` 一个包就占 32 条（16 个唯一编号）**，是本轮最需要优先处理的组件。
3. **必须区分"项目真实依赖"与"venv 环境噪声"**：`后端flask\.venv` 中混入了与本项目无关的 Fedora 发布工程工具链（Twisted / koji / fedora-messaging / pyOpenSSL 等）。按此口径拆分，**75 条中 53 条命中项目真实依赖或由其引入的传递依赖，18 条来自非项目依赖**。
4. **本轮修正了一次严重的扫描失真**：10:49 生成的旧版 `pip.txt` 因 `pip-audit` 未指定输入清单，实际扫描的是**全局 Python 3.13 环境**，报出 122 条命中并包含 `torch`、`keras`、`pillow`、`pytest`、`fsspec`、`ida-pro-mcp` 等与本项目完全无关的包。该结果已作废，**本报告全部数据来自 11:08 后的重扫结果**。
5. **`osv-scanner` 未取得有效结果**：该版本无法解析 `requirements.txt`（报 `found 0 packages`），且对前端 186 个包报 `No issues found`，与 `npm audit`/OSV 库的实际数据矛盾，判定为不可信，未纳入统计。
6. 综合判断：**前端依赖安全已达标；后端问题集中在 4 个可直接升级的包上，属"版本陈旧、修复版本现成"的类型，风险可控、处置成本低**。

## 2. 扫描实施情况

### 2.1 工具、命令与范围

| 工具 | 生态 | 实际命令 | 扫描对象 | 结果 |
| --- | --- | --- | --- | --- |
| `npm audit` | Node / Vue | `npm audit --prefix v1-zhognshe-rebuild-3-vue` | `package-lock.json`，186 个依赖（prod 126 / dev 61 / optional 52） | 首轮 13 条 → 修复后 **0 条** |
| `npm audit`（JSON） | Node / Vue | `npm audit --prefix ... --json` | 同上 | 归档证据 |
| `pip-audit 2.10.1` | Python | `pip-audit -s osv -r 后端flask\requirements.txt` | `requirements.txt`，**63 个包**（venv 全量冻结快照） | **10 个包受影响 / 75 条 / 39 个唯一 ID** |

**关键环境设置（决定结果是否可信）：**

| 设置 | 值 | 为什么必须 |
| --- | --- | --- |
| `$env:PYTHONUTF8` | `1` | 源码路径含中文（`综设1重构`）。中文版 Windows 下 Python 的 stdout 默认编码为 **GBK**，"综"字在 GBK 中无对应码位，会被替换为 `\ufffd`，导致**路径传入工具后变乱码 → 解析到 0 个依赖 → 却报 "No known vulnerabilities found" 的假成功**。实测：不加此变量时路径长度由 47 变为 55 且与原文不相等，加上后完全一致。 |
| 扫描对象 | 显式 `-r requirements.txt` | `pip-audit` 不带 `-r` 时会自行探测 PATH 中的 Python 解释器，**即使已 `activate` 虚拟环境也不会扫描该 venv**，而是扫全局环境。 |

## 4. 后端依赖成分分析

`requirements.txt` 共 63 个包，但其中相当一部分与本项目无关。

| 分类 | 数量 | 说明 |
| --- | ---: | --- |
| **明确项目真实依赖** | **25** | flask、flask-cors、SQLAlchemy、Werkzeug、bcrypt、cryptography、gmssl、PyJWT、python-dotenv、PyMySQL、Jinja2、click、itsdangerous、MarkupSafe、blinker、greenlet、cffi、pycparser、six、python-dateutil、charset-normalizer、certifi、urllib3、idna、requests |
| **明确噪声（Fedora 发布工程工具链）** | **29** | Twisted、koji、fedora-messaging、python-bugzilla、requests-gssapi、grpcio、protobuf、pika、pyasn1、pyasn1-modules、pyOpenSSL、service-identity、googleapis-common-protos、rpds-py、jsonschema、jsonschema-specifications、referencing、atty 系（attrs、Automat、constantly、Incremental、hyperlink）、crochet、decorator、defusedxml、packaging、tomli、wrapt、pycryptodomex |
| **未归类（同源疑为噪声）** | **9** | anitya-schema、fedora-messaging-the-new-hotness-schema、the-new-hotness、zope.interface、v1、redis、colorama、typing-extensions |

**佐证**：对 `后端flask` 源码（排除 `.venv`）实际 `import` 的第三方包进行静态提取，结果仅为：

```
bcrypt  cryptography  dotenv  flask  flask_cors  gmssl  jwt  sqlalchemy  werkzeug
```

即 **9 个第三方模块**，与"25 个明确真实依赖"的量级吻合，而 Twisted / koji / fedora-messaging 等从未被项目代码引用。

**成因推断**：该 venv 在历史某次操作中被安装了 Fedora 发布工程相关包（`the-new-hotness` / `fedora_messaging` / `koji` 属同一依赖族），把这些依赖一并带入。**这不影响依赖扫描本身的正确性**——扫描如实反映了环境现状——但会显著放大漏洞条数并干扰优先级判断。

## 5. osv-scanner 尝试与失效分析

按基线计划，第 2 层拟使用 `osv-scanner` 以"一份报告覆盖前后端"。实际执行未能取得有效结果，产物为 `osv-scanner.txt`（10:58）。

### 5.2 两项失效

| 问题 | 现象 | 判定 |
| --- | --- | --- |
| 后端完全未覆盖 | 对 63 行的 `requirements.txt` 报 `found 0 packages` | 该版本 `osv-scanner` 不支持解析 `requirements.txt`（v1 的已知限制），**后端实际未被扫描** |
| 前端结论不可信 | 对 186 个包报 `No issues found` | 同一 `package-lock.json` 的同一批包，`npm audit` 报出 13 条、OSV 库对 axios/lodash 等报出大量公告，**"零发现"与事实矛盾**，判为漏洞库未生效或版本过旧 |

### 5.3 处置

`osv-scanner` 结果**未纳入本报告统计**。其后端覆盖需求已由 `pip-audit -s osv` 满足——二者查询的是同一个 `https://api.osv.dev` 漏洞库，前端覆盖由 `npm audit` 满足。**在最终结论层面，osv-scanner 的缺失不造成覆盖遗漏。**

# UTF-16LE → UTF-8 无 BOM，避免跨平台工具与 git diff 异常
$f = "$R\后端flask\requirements.txt"
Set-Content -Path $f -Value (Get-Content $f -Encoding Unicode) -Encoding utf8

# 后续所有命令输出均显式指定编码，不要用裸 > 重定向
pip-audit -s osv -r $f 2>&1 | Out-File -Encoding utf8 "$R\扫描结果\依赖扫描\pip.txt"
```

### 7.4 纳入流水线（防止回归）

```

配合 Dependabot / Renovate 定期重扫——漏洞库每日更新，本次的"干净"结论具有时效性。
